# Worktime

Небольшое веб-приложение для учёта рабочего времени. Сотрудник запускает задачу с описанием и останавливает таймер. Администратор создаёт сотрудников и просматривает отчёты. Дополнительное расширение Chrome учитывает время на страницах, простой и блокировку компьютера.

Все демоаккаунты, имена и задачи вымышлены. ИИ использовался для разработки; приложение не отправляет данные в ИИ-сервисы.

## Быстрый запуск

Нужен **Python 3.11 или новее**. Python-пакеты устанавливать не требуется.

```bash
python3 app.py --demo
```

Откройте **http://127.0.0.1:8765**. На macOS можно дважды нажать `Start.command`, на Windows — `Start.bat` (при установленном Python).

| Роль | Логин | Пароль демоаккаунта |
| --- | --- | --- |
| Администратор | `admin` | `admin-demo-2026` |
| Сотрудник | `anna` | `anna-demo-2026` |
| Сотрудник | `oleg` | `oleg-demo-2026` |

Демо создаётся только в пустой базе. Повторный запуск сохраняет изменения и не добавляет примеры заново. Завершение — `Ctrl+C` в окне сервера.

Для чистого проекта без демоданных:

```bash
python3 app.py --db data/clean.sqlite3
```

При первом запуске программа попросит создать администратора. Затем добавьте сотрудников через интерфейс. Пароль вводится скрыто и хранится в виде PBKDF2-SHA256 с индивидуальной солью.

Если порт занят: `python3 app.py --demo --port 8766`. В расширении укажите тот же порт.

## Как пользоваться

1. Войдите администратором. Раздел **«Сотрудники»** → имя, логин и первоначальный пароль → **«Добавить сотрудника»**.
2. В разделе **«Обзор»** выберите сотрудника, заполните описание задачи и нажмите **«Начать задачу»**. Сам сотрудник видит только себя.
3. Нажмите **«Остановить»**, когда закончите работу. У каждого сотрудника может быть только одна активная задача.
4. Откройте **«Отчёты»**, выберите даты и при необходимости сотрудника. Будут показаны записи, итоги по людям и статистика страниц.

Права проверяются на сервере. Сотрудник не может читать чужие отчёты, создавать пользователей или управлять чужими таймерами. Администратор может делать это для всей команды. Сессия входа действует 12 часов и отзывается при выходе.

Данные хранятся в `data/worktime.sqlite3`. Закрытие вкладки и перезапуск приложения не сбрасывают активную задачу: сохраняется время её начала. В общем времени задачи учитывается весь интервал до остановки, включая простой и отсутствие наблюдений.

## Расширение Chrome

Chrome 120 или новее. Расширение устанавливается локально:

1. Откройте `chrome://extensions` и включите **«Режим разработчика»**.
2. Нажмите **«Загрузить распакованное расширение»** и выберите папку `extension` из проекта.
3. В приложении выберите сотрудника и раскройте **«Подключить расширение»**. Скопируйте код подключения.
4. Откройте расширение, укажите `http://127.0.0.1:8765`, вставьте код и нажмите **«Подключить и включить»**.
5. Запустите задачу. Перейдите на несколько обычных сайтов, затем остановите задачу и откройте отчёт.

Учёт работает только при запущенной задаче. Код привязывает расширение к одному сотруднику; используйте одно подключённое расширение на сотрудника. Кнопка **«Выключить наблюдение»** отключает сбор, сам таймер продолжает работать.

Разрешения: `tabs` — адрес и заголовок активной вкладки, `idle` — простой/блокировка, `alarms` — периодический опрос, `storage` — настройки и очередь. Доступ к серверу ограничен `localhost` и `127.0.0.1`.

### Что означает статистика

- **Страницы** — выбранная вкладка, когда окно браузера на переднем плане и система не в состоянии простоя.
- **Простой** — блокировка либо отсутствие ввода в течение 5 минут. Первые 5 минут без действий ещё считаются активным состоянием по этому правилу.
- **Вне страниц** — система активна, но на переднем плане другое приложение или неотслеживаемая служебная вкладка.
- **Без наблюдения** — расширение не подключено, сервер недоступен, браузер закрыт или произошёл большой перерыв между наблюдениями.

Сохраняются адрес без параметров, фрагмента и учётных данных, название страницы и длительность. Содержимое страниц, снимки экрана и нажатые клавиши не собираются. Приватные вкладки исключены.

Опрос происходит каждые 30 секунд, а также при смене вкладки, фокуса и состояния простоя. Это приблизительное наблюдение: возможна погрешность около одного интервала опроса. Chrome может задерживать фоновые события. Перерыв более 90 секунд остаётся без наблюдения и не приписывается последнему сайту. При остановке задачи ненаблюдённый хвост может сохраняться до следующего опроса. Обновление отчёта — каждые 15 секунд.

Повторная доставка события не удваивает время; пересечения и границы задачи обрезаются сервером. Очередь ограничена 240 событиями. При переполнении старые наблюдения отбрасываются и остаются без наблюдения.

Повторное подключение с прежним адресом и кодом сохраняет очередь. Если в ней есть неотправленные события, смена сотрудника или адреса не удаляет их: сначала восстановите прежнее подключение и дождитесь отправки. Возобновление после паузы не приписывает время паузы активности.

Категории «Документы», «Разработка», «Видео», «Другие» определяются прозрачными правилами в `worktime/store.py`. Они не оценивают продуктивность: просмотр видео или чтение без движений мышью может быть частью работы.

## Периоды и подсчёт

Даты и время в отчётах — **UTC**, обе выбранные даты включены. Запись, пересекающая полночь, даёт в каждом периоде только соответствующую часть времени. Активная задача считается до текущего серверного времени. Пустой отчёт возвращает нулевые итоги и пустой список записей, включая сотрудников без задач.

Общее время = страницы + простой + время вне страниц + время без наблюдения. Отображение округляется вниз до секунды, в базе сохраняются дробные секунды.

## Тема и React-компонент

Тема адаптирована из предоставленного примера: моноширинный системный шрифт, нейтральные светлые/тёмные поверхности, синие акценты, карточки со скруглением. Тема переключается кнопкой в верхней панели. Внешние шрифты и CDN не нужны.

Основной интерфейс работает **без Node.js и сборки**. В нём есть перестановка сводных карточек мышью и клавиатурой: **«Настроить виджеты»**, затем перетаскивание или `Alt` + стрелки. Порядок сохраняется в браузере.

Для предоставленной React-сетки добавлен отдельный путь сборки:

- `components/ui/draggable-widget-grid.tsx` — адаптация компонента из задания, Motion-анимация, клавиатурное управление и удержание на сенсорных экранах;
- `src/widgets.tsx` — подключение сетки к фактическим данным приложения;
- `src/index.css` — Tailwind CSS 4 и токены темы;
- `components.json` — структура shadcn/ui;
- `tsconfig.json`, `vite.config.mts` — TypeScript, алиас `@/` и сборка.

**Важно:** в среде подготовки не было Node.js, а сеть для установки пакетов была заблокирована. React-сборка и её визуальная работа здесь не проверены. Файлы `static/widgets.js` и `static/widgets.css` не включены. При их отсутствии используется обычная сетка; остальная функциональность доступна.

Чтобы собрать React-вариант, установите Node.js **20.19+** или **22.12+**, затем в корне проекта:

```bash
npm install
npm run build
python3 app.py --demo
```

`motion` уже указан в `package.json`; отдельная установка — `npm install motion`. После сборки Vite сохранит два дополнительных файла в `static`, и приложение автоматически подключит React-сетку. Python API при этом не меняется. TypeScript проверяется командой `npm run typecheck`.

Путь компонентов — **`components/ui` от корня проекта**, импорт — `@/components/ui/...`. Эта папка нужна для совместимости с shadcn CLI и переданными импортами. Внешние компоненты удобно хранить отдельно от прикладных модулей. Основные стили — `static/style.css`, стили React/Tailwind — `src/index.css`.

Для добавления стандартных компонентов shadcn после `npm install`:

```bash
npx shadcn@latest add button
```

Настройки уже подготовлены, повторно выполнять `init` не требуется. Если разворачиваете отдельный проект с нуля, официальный старт: `npx shadcn@latest init --template vite`. См. [настройку Vite/shadcn](https://ui.shadcn.com/docs/installation/vite) и [установку Motion](https://motion.dev/docs/react-installation).

## Проверки

Python-проверки не требуют установки пакетов:

```bash
python3 -m unittest discover -v
```

JavaScript-проверки при установленном Node.js:

```bash
npm test
node scripts/syntax-check.js
```

На macOS/Linux все доступные проверки запускаются `sh scripts/check.sh`. На этом Mac JavaScript проверялся через системный JavaScriptCore, поскольку Node.js отсутствовал.

Проверяются сохранение после перезапуска, повторный и одновременный старт, остановка и повторная остановка, новая задача после завершения, пустой отчёт, границы дат, доставка и пересечение интервалов, очистка URL, вход/выход, срок сессии, права администратора и сотрудника. Есть сквозной сценарий через WSGI: вход → задача → событие расширения → остановка → перезапуск → отчёт.

GitHub Actions настроен на Python-проверки, JavaScript и сборку React. Он выполнится после самостоятельной загрузки проекта в GitHub; успешный запуск CI заранее не заявляется. `package-lock.json` не создавался, поскольку зависимости здесь не устанавливались. После первого `npm install` добавьте полученный lock-файл в репозиторий.

Точный результат локальных проверок и ограничения — в [docs/verification.md](docs/verification.md).

Повторная сверка с ТЗ, отзывы пользователей, ответы разработчиков похожих продуктов и дополнительные исправления — в [docs/audit.md](docs/audit.md). После аудита успешно выполнены 54 Python-теста и 32 JavaScript-проверки.

## Использование ИИ

Код, тесты и документация подготовлены с **OpenAI Codex**. Среда описывает модель как относящуюся к семейству **GPT-6**; точный идентификатор и версию модели в этой сессии подтвердить нельзя. Другие модели и инструменты генерации кода не использовались. Дополнительные агенты не запускались.

Примеры фактических запросов, которые определили реализацию:

> «Создайте с нуля небольшое веб-приложение для учёта рабочего времени сотрудников компании».

> «Можешь проверять время экран и мышь когда активны».

> «Анализ страниц которые открывал в это время сотрудник допустим?»

> «Предусмотри разные роли создание новых сотрудников» и «Вход с паролем: администратор и сотрудник».

> Предоставленный `DraggableWidgetGrid` и запрос «Примени тему».

ИИ использовался не только для генерации: требования уточнялись до реализации, критичные сценарии сначала закреплялись тестами, код отдельно проверялся на повторные запросы, доступ к чужим данным и границы интервалов. Документация Chrome, Python, shadcn и Motion использовалась для проверки API. Ниже приведены реальные обнаруженные ошибки.

### Найденные и исправленные ошибки

1. **При переводе системных часов назад активность могла стать длиннее завершённой задачи.** Воспроизведение: записать 60 секунд активности, перевести часы на 40 секунд назад, остановить задачу и снова продвинуть время. Отчёт показывал 20 секунд задачи и 60 секунд страницы. Исправление: интервалы в отчёте дополнительно ограничиваются началом и концом самой задачи. Тест `test_clock_rollback_does_not_make_activity_exceed_task` сначала падал (`60 != 20`), после исправления проходит.
2. **После выхода данные предыдущего пользователя оставались в скрытых элементах страницы.** Сам API уже ограничивал доступ, но таблицы и код расширения требовали очистки. Исправление: выход очищает данные, код и React-сводку; ответы старых запросов не применяются к новому входу. Проверки `tests/interface.test.js` сначала выявили четыре ошибки очистки, после исправления проходят.
3. **Обновление статуса расширения перезаписывало редактируемые настройки в его окне.** При проверке кода найдено, что `refresh()` заново заполнял поля при каждом изменении статуса. Теперь настройки заполняются только при первоначальном открытии. Эта правка проверена чтением кода и синтаксической проверкой; отдельная проверка в Chrome не проводилась.
4. **Переподключение расширения удаляло очередь неотправленных событий.** Теперь прежнее подключение сохраняет очередь и актуальный снимок состояния; смена сотрудника с незавершённой доставкой не очищает данные молча. Сценарии закреплены в `tests/extension.test.js`.
5. **Старый ответ 401 мог сбросить новый вход.** Ответы API учитывают поколение входа, начальная загрузка также не применяет устаревший результат. Проверка воспроизводит запоздавший ответ после переключения пользователя.
6. **Очистка при выходе была неполной.** Дополнительно очищаются описание активной задачи, имя аккаунта, списки выбора и незавершённая форма создания сотрудника, включая пароль. Проверки сначала обнаружили четыре оставшихся значения, после исправления проходят.
7. **Большой числовой ID приводил к HTTP 500 вместо ошибки запроса.** Добавлена проверка диапазона целых SQLite для сотрудников и задач, включая остановку и события расширения. Регрессионные проверки теперь получают HTTP 400.
8. **Страница без фактического времени могла попасть в отчёт после перевода часов.** Наблюдения с нулевым пересечением с задачей исключаются; отдельный тест проверяет пустой список таких страниц.

## Устройство проекта

```text
app.py                 запуск и вымышленные демоданные
worktime/store.py      SQLite, задачи, интервалы и отчёты
worktime/auth.py       пароли, пользователи, сессии входа
worktime/web.py        WSGI API и проверка прав
```

## Ограничения и передача

Приложение предназначено для локального тестового. Встроенный WSGI-сервер слушает только `127.0.0.1`; это не публичный сервер для компании. Учёт браузера не охватывает содержимое других программ и не доказывает продуктивность.

Для передачи кода загрузите содержимое папки проекта в новый публичный репозиторий. Базу `data/`, `node_modules/`, кэш и личные данные загружать не нужно — они исключены через `.gitignore`. Демо будет создано при запуске у проверяющего. Первая версия уже опубликована пользователем: https://github.com/aichurekmilashka-wq/-. Проверенные исправления подготовлены для обновления этого репозитория. Демо не опубликовано.
