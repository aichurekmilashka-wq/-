# Размещение бесплатного демо

Согласовано: бесплатный Render, общие вымышленные данные; SQLite сбрасывается при перезапуске сервиса. Основной локальный вариант с сохранением данных остаётся доступен.

План ограниченного изменения:

1. Закрепить тестами HTTPS, допустимый Host/Origin, Secure-cookie, health check, баннер демо и повторный запуск с существующей БД.
2. Добавить Gunicorn factory `hosted:create_app()`, запускающую ту же Application и SQLite.
3. Добавить настройки бесплатного Render в корень репозитория, без платного диска и автоматического повышения тарифа.
4. Расширение разрешает HTTPS к onrender.com только после разрешения пользователя для конкретного сервера.
5. Проверить локально и в GitHub Actions; после подключения Render развернуть сервис, получить фактический адрес и проверить его ответы.

Завершение размещения зависит от добавления Render пользователем. Ссылка на демо появится только после успешного развёртывания.

Настройки подготовлены в корневом `render.yaml`: web service, `plan: free`, Docker, папка `Worktime Tracker`, health check `/healthz`. Платный диск не создаётся. Адрес берётся из `RENDER_EXTERNAL_URL`, который Render задаёт автоматически.

Docker собирает предоставленные React-виджеты, затем запускает приложение через Gunicorn. В CI отдельная проверка `hosted` собирает этот образ и обращается к настоящему HTTP-серверу: проверяет страницу, наличие React-bundle, вход, создание сотрудника, повторный старт, остановку, отчёт и выход.

У демо общая база с вымышленными аккаунтами. Изменения видны другим посетителям. Данные хранятся до перезапуска/переразвёртывания/сна бесплатного сервиса. В интерфейсе об этом есть заметная пометка. Локальный запуск по-прежнему хранит базу на диске.

Документация: [бесплатный Render](https://render.com/docs/free), [переменные среды](https://render.com/docs/environment-variables).
