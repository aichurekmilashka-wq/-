48 Python-тестов включают полный сценарий через WSGI: вход сотрудника, старт задачи, авторизованное событие расширения, остановка, повторное создание приложения и отчёт с сохранёнными данными. Используются временные SQLite-базы и управляемые часы. Параллельные старты проверяются настоящими потоками и соединениями SQLite.

JS-проверки выполняют фактическую логику расширения. Для проверки очистки интерфейса используется небольшая имитация DOM; она не заменяет запуск в браузере.

Найденные регрессии «перевод часов» и «старые данные после выхода» воспроизведены падающими проверками до исправления. Подробности — в README.

## Что не проверено

- **Запуск HTTP-сервера и визуальная работа в браузере:** среда запрещает открытие локального порта (`Operation not permitted`), инструмент управления браузером недоступен. Проверен WSGI-контракт без сети.
- **Фактическая загрузка расширения в Chrome:** Chrome и управление им в этой среде недоступны. Проверены чистая логика, синтаксис и формат manifest.
- **React/TypeScript/Tailwind-сборка и Motion-анимация:** Node.js/npm отсутствуют, скачивание пакетов из этой среды заблокировано. В проекте есть исходник, интеграция, зависимости и настройки сборки; готовый React-bundle не заявляется.
- **GitHub Actions:** конфигурация добавлена, удалённого запуска не было. Репозиторий пользователь загрузит самостоятельно.

Основной интерфейс не требует React-bundle: предусмотрена обычная сетка с той же темой, таймером, ролями и отчётами. Для завершения проверки React-варианта на машине с Node.js выполните `npm install`, `npm run build` и проверьте перетаскивание мышью, удержание на сенсорном экране и `Alt` + стрелки.

## Проверка вручную после запуска

1. `python3 app.py --demo`, открыть http://127.0.0.1:8765.
2. Войти `admin`, добавить вымышленного сотрудника, выйти и войти его логином.
3. Запустить задачу, обновить страницу, убедиться, что время продолжается; попытаться повторно запустить таймер.
4. Подключить расширение кодом этого сотрудника; переключить несколько обычных страниц и другое приложение.
5. Остановить задачу, открыть отчёт. Проверить итог, страницы и время без наблюдения.
6. Выбрать период без записей: итоги равны нулю, ошибки нет.
7. Перезапустить приложение с той же БД: сотрудники, записи и вход сохранены.
8. Сотруднику недоступен раздел добавления сотрудников; его отчёт содержит только собственные данные.
9. Переключить светлую/тёмную тему и проверить мобильную ширину.
